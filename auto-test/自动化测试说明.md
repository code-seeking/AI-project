## 1. 项目概述

本测试套件覆盖 **HR 候选人 AI 管理系统** 的全部 5 个前端页面，共计 **54 个 UI 自动化测试用例** 和 **44 个 API 接口测试用例**。

| 类型 | 用例数 | 通过率 | 框架 |
|------|--------|--------|------|
| UI 页面测试 | 54 | 100% | Playwright 1.60.0 + Chromium |
| API 接口测试 | 44 | 100% | Playwright 1.60.0 |

**被测系统技术栈：**

| 层级 | 技术 |
|------|------|
| 前端 | Vue 3 + Vite 6.4.2 + Element Plus + TypeScript |
| 后端 | Spring Boot 3.4.5 + MyBatis-Plus |
| 数据库 | MySQL 8.0.39 |
| 缓存 | Redis |
| AI | Anthropic Claude API (via cc-vibe.com) |

### 2.2 配置文件说明

#### `playwright.ui.config.ts`（UI 测试配置）

```typescript
import { defineConfig } from '@playwright/test';

export default defineConfig({
  testDir: './tests/ui',           // UI 测试文件目录
  timeout: 60_000,                 // 单个用例超时 60秒
  expect: { timeout: 10_000 },     // 断言超时 10秒
  fullyParallel: false,            // 串行执行（同 describe 内顺序执行）
  retries: 0,                      // 不重试
  reporter: [
    ['list'],                                              // 控制台输出
    ['html', { outputFolder: 'test-results/ui-report' }],  // HTML 报告
    ['json', { outputFile: 'test-results/ui-results.json' }], // JSON 结果
  ],
  use: {
    baseURL: 'http://localhost:5173',  // 前端地址
    screenshot: 'on',                  // 每个断言自动截图
    viewport: { width: 1440, height: 900 },
    locale: 'zh-CN',
  },
  projects: [
    {
      name: 'chromium',
      use: { browserName: 'chromium', channel: 'chrome', headless: true },
    },
  ],
  outputDir: 'test-results/ui-screenshots',  // 截图输出目录
});
```

#### `playwright.config.ts`（API 测试配置）

用于 API 接口测试，`baseURL` 指向后端 `http://localhost:8080`。

### 2.3 测试执行模式

- **串行模式**（`fullyParallel: false`）：同一 `describe` 块内的测试按顺序执行
- **失败跳过**：某个测试失败后，同一 `describe` 内后续测试自动跳过
- **前置依赖**：部分测试（如候选人详情）在 `beforeAll` 中通过 API 获取测试数据

### 8.2 需新建部分（核心工作量）

**测试用例文件（`.spec.ts`）** 需要根据新项目的页面功能重新编写。

#### 步骤一：分析目标项目

1. 梳理所有页面路由（查看 `router/index.ts`）
2. 理解每个页面的功能（查看 `views/*.vue`）
3. 确定 Element Plus 组件使用方式（`el-table`、`el-dialog`、`el-form` 等）

#### 步骤二：编写测试用例

每个 `.spec.ts` 文件的基本结构：

```typescript
import { test, expect } from '@playwright/test';

test.describe.serial('页面名称 UI 自动化测试', () => {

  test.beforeEach(async ({ page }) => {
    // 每个测试前导航到目标页面
    await page.goto('/目标路由');
    await page.waitForLoadState('networkidle');
  });

  test('用例1: 页面加载验证', async ({ page }) => {
    // 验证关键元素存在
    await expect(page.locator('.el-table')).toBeVisible();
    await expect(page.locator('.el-pagination')).toBeVisible();
    // 截图
    await page.screenshot({ path: 'test-results/ui-screenshots/01-loaded.png' });
  });

  test('用例2: 搜索功能', async ({ page }) => {
    const input = page.locator('.el-input input').first();
    await input.fill('搜索关键词');
    await page.locator('button:has-text("搜索")').click();
    await page.waitForLoadState('networkidle');
    // 验证搜索结果
    await expect(page.locator('.el-table__body-wrapper')).toBeVisible();
  });

  test('用例3: 新增功能', async ({ page }) => {
    await page.locator('button:has-text("新增")').click();
    const dialog = page.locator('.el-dialog');
    await expect(dialog).toBeVisible();
    // 填写表单...
    // 提交...
    // 验证成功提示
  });
});
```

#### 步骤三：常用选择器速查

| 场景 | Playwright 选择器 |
|------|-------------------|
| Element Plus 表格 | `.el-table` |
| 表格行 | `.el-table__body-wrapper .el-table__row` |
| 分页器 | `.el-pagination` |
| 对话框 | `.el-dialog` |
| 对话框关闭 | `.el-dialog__header` (点击空白处关闭下拉) |
| 对话框确认 | `.el-dialog__footer button:has-text("确定")` |
| 对话框取消 | `.el-dialog__footer button:has-text("取消")` |
| 表单输入 | `.el-form-item .el-input input` |
| 下拉选择 | `.el-select` |

### Q4: 截图文件在哪里？

每个测试用例会在关键断言处自动截图（配置 `screenshot: 'on'`）。

### Q5: 如何查看上一次测试的结果？

```powershell

# 或直接打开专业报告

```

### Q6: 测试执行很慢怎么办？

- 默认串行执行（`fullyParallel: false`），54个用例约 1.5~2 分钟
- 可只运行单个页面的测试来加快速度
- 调试时用 `--headed` 模式可以看到浏览器操作过程

### Q7: 如何使用 Playwright 录制功能生成测试代码？

```powershell
npx playwright codegen http://localhost:5173
```

会打开浏览器和代码生成器，录制你的操作并自动生成 Playwright 测试代码。

### Q8: `--config` 参数必须指定吗？

- **UI 测试**：必须指定 `--config=playwright.ui.config.ts`，否则会默认使用 `playwright.config.ts`（API 测试配置）
- **API 测试**：可以省略，`playwright.config.ts` 是默认配置
