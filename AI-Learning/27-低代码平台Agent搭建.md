# 第 27 课：低代码平台 Agent 搭建

> **核心问题**：不是所有 Agent 都需要写代码。什么时候用平台？什么时候自己写？
> **预计时间**：1-2 天
> **前置知识**：第 09 课（AI Agent）、第 11 课（AI 工作流引擎）

---

## 一、为什么需要低代码 Agent 平台？

```
类比（Java 开发视角）：
  手写 Agent = 用 JDBC 操作数据库（灵活但繁琐）
  低代码平台 = 用 Spring Data JPA（抽象好、上手快）

适用场景：
  - 快速验证 Agent 想法（MVP / Demo）
  - 非开发人员搭建 AI 应用（运营、HR）
  - 标准化场景快速上线（知识库问答、客服）

不适用场景：
  - 需要深度定制业务逻辑
  - 需要与内部系统紧密集成
  - 对性能/安全有极高要求
```

## 二、四大平台对比

| 平台 | 定位 | 核心优势 | 适合场景 | 开源 |
|------|------|---------|---------|------|
| Coze（字节） | 一站式 Bot 平台 | 插件生态、一键发布飞书/微信 | 快速原型 | 否 |
| Dify | 开源 LLM 应用平台 | 完整 RAG 管线、可视化编排 | 企业知识库 | 是 |
| FastGPT | 开源知识库问答 | 开箱即用的文档问答 | 客服/文档 | 是 |
| n8n | 开源工作流自动化 | 400+ 集成节点 | 复杂自动化 | 是 |

## 三、Coze（字节跳动）

### 3.1 核心能力

```
- 人设与对话：配置 System Prompt 定义 Bot 角色
- 插件市场：搜索引擎、网页解析、代码执行等即插即用
- 工作流编排：可视化拖拽定义多步骤流程
- 多渠道发布：一键发布到飞书、微信、网页、API
- 知识库：上传文档自动构建 RAG
```

### 3.2 实战案例：搭建"每日 AI 简报"助手

```
1. 创建 Bot -> 人设："你是 AI 行业资讯分析师"
2. 添加插件：搜索引擎 + 网页解析
3. 配置工作流：搜索 -> 解析文章 -> 提取关键信息 -> 生成简报
4. 设置定时触发器：每天 09:00
5. 发布到飞书群

优势：5 分钟上线，零代码
局限：插件生态依赖字节，私有化部署不可能
```

### 3.3 优势与局限

```
优势：
  + 上手极快：拖拽配置，分钟级上线
  + 生态丰富：内置插件 + 模板
  + 发布便捷：多平台一键分发

局限：
  - 不开源：数据在字节云上，企业敏感数据慎用
  - 定制有限：复杂业务逻辑无法实现
  - 厂商锁定：迁移成本高
```

## 四、Dify（开源 LLM 应用平台）

### 4.1 核心能力

```
- 完整 RAG 管线：文档上传 -> 切块 -> Embedding -> 检索 -> 生成
- 可视化编排：Chatflow / Workflow 两种模式
- 多模型支持：OpenAI / Claude / 本地 Ollama 均可接入
- API 优先：每个应用自动生成 REST API
- 私有化部署：Docker 一键部署，数据不出域
```

### 4.2 实战案例：搭建"HR 政策问答机器人"

```
1. 上传知识库：公司员工手册、招聘制度、面试规范
2. 切块策略：按章节切块，500 token/段
3. 创建 Agent 应用，关联知识库
4. 添加工具：SQL 查询（查候选人状态）
5. 配置对话流程：
   政策问题 -> 知识库检索 -> 生成回答（附引用）
   数据查询 -> 意图识别 -> SQL 工具 -> 格式化输出
6. 发布为 API，集成到 HR 系统前端

优势：RAG 能力强，支持私有化
局限：复杂多 Agent 编排能力弱于专业框架
```

### 4.3 优势与局限

```
优势：
  + 开源可私有化：数据完全自控
  + RAG 管线成熟：切块/检索/重排全流程
  + 模型无关：随时切换底层 LLM

局限：
  - 工作流复杂度有限：不支持动态多 Agent 协作
  - 社区版功能受限：企业功能需付费
  - Java 集成需通过 API，不如原生代码灵活
```

## 五、FastGPT（开源知识库问答）

### 5.1 核心能力

```
- 专注文档问答：开箱即用的 RAG 方案
- 多文档格式支持：PDF / Word / Markdown / CSV
- 可视化工作流：简单的流程编排
- 嵌入便捷：iframe 一行代码嵌入网站
```

### 5.2 实战案例：搭建"技术面试知识库助手"

```
1. 上传面试题库、技术评估标准
2. 配置切分策略：按题目类型切分
3. 创建工作流：意图识别 -> 分类检索 -> 生成回答
4. 嵌入到面试官工具页面

优势：文档问答场景做到极致
局限：只适合问答，不适合复杂 Agent 任务
```

## 六、n8n（开源工作流自动化）

### 6.1 核心能力

```
- 400+ 集成节点：Gmail / Slack / GitHub / 数据库 / HTTP...
- AI 节点：LLM 调用、向量存储、Agent 作为工作流节点
- 自托管：Docker 部署，数据自控
- 代码扩展：JavaScript / Python 自定义节点
```

### 6.2 实战案例：搭建"智能邮件招聘助手"

```
工作流设计：
1. 触发器：新邮件到达（Gmail 节点）
2. LLM 节点：分析邮件类别（应聘/咨询/其他）
3. 条件分支：
   - 应聘邮件 -> 提取简历附件 -> 调用 HR 系统 API 入库
   - 咨询邮件 -> 知识库检索 -> 自动回复
   - 其他 -> 标记 + 通知 HR
4. 审计：所有操作记录到日志表

优势：系统集成能力极强
局限：AI 能力不如专业平台深
```

## 七、选型决策树

```
你的需求是什么？
|
+-- 快速验证想法 / 做 Demo
|   +-- 需要发布到 IM -> Coze
|   +-- 只需本地测试 -> Dify
|
+-- 企业知识库问答（需私有化）
|   +-- 纯文档问答 -> FastGPT
|   +-- 需要工具调用 -> Dify
|
+-- 复杂自动化流程（多系统集成）
|   +-- 偏 AI 驱动 -> Dify + 自定义 API
|   +-- 偏流程驱动 -> n8n
|
+-- 深度定制 / 集成到 Java 项目
    +-- 自己写（Spring AI / LangChain4j）
```

## 八、用 AI 工具实际体验

### 8.1 用 Dify 搭建 HR 政策问答机器人 —— 实际操作流程

```
步骤 1：部署 Dify
  $ docker compose up -d
  访问 http://localhost/apps

步骤 2：创建知识库
  点击「知识库」→「创建知识库」→ 上传文件
  上传：员工手册.pdf、招聘制度.docx、面试规范.md
  切块策略：自动切块，500 token/段，重叠 50 token

步骤 3：创建应用
  点击「创建空白应用」→ 选择「聊天助手」
  模型选择：GPT-4o（或本地 Ollama/Qwen2）

步骤 4：配置系统提示词
  输入：
  """
  你是公司 HR 政策问答助手。基于知识库中的文档回答员工问题。
  规则：
  1. 只基于知识库内容回答，不编造信息
  2. 如果知识库中没有相关信息，明确告知用户
  3. 回答时引用来源文档名称
  """

步骤 5：关联知识库
  「上下文」→「添加知识库」→ 选择刚创建的知识库

步骤 6：测试对话
  问：「年假有多少天？」
  答：「根据公司员工手册第 3 章第 2 节：
      - 入职满 1 年：5 天年假
      - 入职满 5 年：10 天年假
      - 入职满 10 年：15 天年假
      来源：员工手册.pdf 第 12 页」

  问：「面试流程是怎样的？」
  答：「根据招聘制度第 4 章：
      1. HR 初筛（电话 15 分钟）
      2. 技术面试（现场 1 小时）
      3. 部门总监面试（30 分钟）
      4. HR 终谈（薪资沟通）
      来源：招聘制度.docx 第 8 页」

步骤 7：发布
  点击「发布」→ 获取 API 地址
  集成到 HR 系统前端
```

### 8.2 用 n8n 搭建智能邮件招聘助手 —— 实际操作流程

```
步骤 1：部署 n8n
  $ docker run -it --rm -p 5678:5678 n8nio/n8n
  访问 http://localhost:5678

步骤 2：创建工作流
  新建工作流 → 添加节点

  节点 1：Gmail Trigger
    配置：监听招聘邮箱，每 5 分钟检查一次

  节点 2：AI Agent（LLM 节点）
    模型：GPT-4o
    System Prompt：
    """
    分析收到的邮件，判断类别：
    - APPLICATION：应聘邮件，提取姓名、应聘岗位、经验年限
    - INQUIRY：咨询邮件，提取问题摘要
    - OTHER：其他邮件
    输出 JSON 格式：{"category": "...", "name": "...", "position": "..."}
    """

  节点 3：IF 条件分支
    条件：{{ $json.category }}

  分支 A（APPLICATION）：
    节点 4a：HTTP Request → 调用 HR 系统 API
      POST /api/candidates
      Body: { name: "{{name}}", position: "{{position}}", source: "email" }
    节点 5a：Gmail → 发送确认邮件
      主题：「感谢应聘 - 我们已收到您的简历」

  分支 B（INQUIRY）：
    节点 4b：Vector Store → 知识库检索
    节点 5b：LLM → 生成回复
    节点 6b：Gmail → 发送回复

  分支 C（OTHER）：
    节点 4c：Slack → 通知 HR 团队

步骤 3：激活工作流
  点击「Active」→ 工作流开始监听邮件

实际效果：
  收到邮件：「您好，我想应聘高级Java开发岗位，附件是我的简历。张三，8年经验」
  → AI 分析：{"category": "APPLICATION", "name": "张三", "position": "高级Java开发"}
  → 自动入库 HR 系统
  → 自动回复确认邮件
  → 全程无需 HR 手动处理
```

## 九、HR 项目中的适用场景

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| HR 政策问答机器人 | Dify / FastGPT | 知识库 + RAG 成熟方案 |
| 候选人自动筛选通知 | n8n | 邮件/系统多集成 |
| AI 面试助手原型 | Coze | 快速验证想法 |
| 深度集成到 HR 系统 | 自己写 | 需要代码级控制 |
| 简历解析 + 入库 | 自己写 | 需要定制解析逻辑 |

## 十、本课小结

```
核心要点：
1. 低代码平台 = Agent 的"快速开发工具"，不是万能药
2. Coze：最快上手，适合原型；Dify：RAG 最强，适合企业
3. FastGPT：文档问答专精；n8n：系统集成之王
4. 选型关键：是否需要私有化、是否需要深度定制
5. Java 项目中：平台做原型验证，自研做生产系统
```
