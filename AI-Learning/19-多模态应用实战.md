## 一、为什么多模态是企业的刚需

```
企业里的真实数据形态：
  PDF 简历（排版复杂、含图片）
  证件照片（身份证、学历证书）
  手写表单、扫描件
  面试录音/视频
  产品截图、UI 设计稿
  合同扫描件、发票

纯文本 LLM 处理不了这些 → 多模态是生产刚需
```

## 三、视觉理解（Vision）

### 3.1 多模态大模型

```
GPT-4o / Claude / Gemini / Qwen-VL / GLM-4V
```

### 3.2 企业应用场景（HR 方向）

## 四、文档解析（PDF/扫描件）

### 4.1 文档解析的层级

```
层级 1：文本提取（PDF 有文字层）
  PDFBox / pdfplumber / pdf.js → 直接提取文字
  局限：复杂排版（多栏、表格）容易乱序

层级 2：OCR（扫描件/图片型 PDF）
  PaddleOCR / Tesseract / 云 OCR（阿里/腾讯/百度）
  局限：手写体、低清扫描件准确率下降

层级 3：版面分析 + 语义理解（文档智能）⭐
  阿里 DocMind / 腾讯 OCR / 开源 Unstructured / MinerU
  能力：识别标题/段落/表格/图片 → 还原阅读顺序
  这是企业级文档解析的主流方案

层级 4：多模态大模型直接读
  GPT-4o / Qwen-VL 直接看图理解文档
  灵活但 token 贵、超大文档受限
```

### 4.2 文档解析管线（生产级）

```
PDF 上传
  → 格式检测（文字型 or 扫描型）
  → 文字型：PDFBox 提取（快）
  → 扫描型：OCR（慢但必要）
  → 版面分析（表格还原、阅读顺序）
  → 清洗（页眉页脚、乱码）
  → 结构化文本（Markdown/JSON）
  → 交给下游（RAG 入库 / LLM 分析）

你的项目实践（记忆确认）："统一简历文本提取实践"
  正是把各种简历格式 → 统一纯文本/结构化数据
```

### 4.3 表格解析（最容易错的部分）

```
难点：
  复杂表头（合并单元格）
  跨页表格（表头重复）
  无边框表格

方案：
  1. 专用表格模型：Table Transformer、阿里表格识别
  2. 提示词技巧：让 LLM 按"行列结构"理解
  3. 多方案融合：OCR 表格 + LLM 修正

验证：解析后的表格要人工抽查 + 结构化校验
```

## 五、语音处理（面试场景核心）

### 5.1 语音转文字（ASR）

```
服务/工具：
  云端：阿里 Paraformer、腾讯 ASR、讯飞、OpenAI Whisper API
  开源：Whisper（本地部署，中文效果不错）
  实时：流式 ASR（面试直播场景）

企业面试场景：
  1. 面试录音 → 转写文本（离线）
  2. 实时面试 → 实时转写（辅助面试官）
  3. 转写文本 → LLM 分析（面试评估）

转写质量影响后续一切：
  口语化、重复词、语气词 → 需要清洗
  方言/专业术语 → 准确率下降，需纠错
```

### 5.2 转写后处理

```
原始转写："那个...嗯...我做过三年的 Java，就是那个...Spring Boot 项目"
清洗后："我做过三年的 Java，主要是 Spring Boot 项目"

清洗步骤：
  1. 去语气词（嗯、啊、那个）
  2. 去重复（结巴修复）
  3. 标点规范化
  4. 分段（按语义）
  5. 说话人分离（多人对话）

然后才能喂给 LLM 做面试评估
```

### 5.3 面试评估的完整链路

```
面试录音 → ASR 转写 → 清洗分段 → LLM 分析
  → 评估维度（表达能力/技术准确/逻辑/风险点）
  → 结构化报告 → 面试官参考

注意：AI 评估只能"辅助"，最终决策必须人工
（招聘合规要求 + 模型幻觉风险）
```

## 六、多模态应用架构要点

### 6.1 管线设计

```
多模态任务 = 解析管线 + LLM 理解

[原始文件] → [解析服务] → [结构化文本] → [LLM 理解] → [业务结果]

解析服务（可独立扩展）：
  图片 → OCR
  PDF → 版面分析
  语音 → ASR
  视频 → 抽帧 + ASR

好处：
  1. 解析结果可复用（同一简历解析一次，多次使用）
  2. 解析失败可单独重试（不影响 LLM 层）
  3. 各环节可独立评估质量
```

### 6.2 成本策略

```
解析环节（OCR/ASR）通常比 LLM 便宜很多：
  优先用便宜的解析服务
  只有复杂理解才用多模态大模型

策略：
  文本型 PDF → PDFBox 免费提取（不 OCR）
  清晰图片 → 便宜 OCR（几厘钱/张）
  复杂文档 → 文档智能服务
  LLM 只做"理解"不做"提取"（能拆就拆）
```

### 6.3 质量评估

```
每个解析环节都要有质量指标：
  OCR：字符准确率（抽样人工核对）
  ASR：字错误率（WER）
  版面：段落还原正确率
  表格：单元格还原正确率

质量不达标 → 触发人工处理流程（质检工单）
```

## 七、多模态实战案例（HR 系统）

```
案例：AI 简历全自动入库

1. 上传 PDF 简历（含扫描件）
2. 格式检测 → 文字型 PDFBox / 扫描型 OCR
3. 版面分析 → 结构化（教育/经历/技能 分节）
4. 结构化数据校验（必填字段检查）
5. 失败样本 → 人工处理队列
6. 成功 → 入库 + 生成文本版（供 Embedding/RAG）
7. 定期抽检 → 质量报告

案例：AI 面试助手
1. 面试录音 → Whisper 转写
2. 清洗分段 + 说话人分离
3. LLM 分析（表达/技术/风险）
4. 生成面试报告 → 面试官复核
```

## 八、本课小结

```
核心要点：
1. 企业数据是多形态的：图片/PDF/语音/视频
2. 文档解析四级：文本提取 → OCR → 版面分析 → 多模态 LLM
3. 表格是最容易出错的部分，需要专门方案
4. 语音：ASR 转写 + 清洗（语气词/重复）+ 说话人分离
5. 管线设计：解析服务（便宜、可复用） + LLM 理解（贵、灵活）
6. 每个环节都要有质量指标和人工兜底
7. AI 评估只能辅助，最终决策必须人工
```
