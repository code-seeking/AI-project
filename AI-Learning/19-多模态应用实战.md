## 三、视觉理解（Vision）

### 核心概念深度解析

### 多模态大模型（Multimodal Large Language Model）

> **严谨定义**：多模态大模型是能够同时处理文本、图像、音频、视频等多种模态数据的大型神经网络。其核心架构通常包括模态编码器（如 ViT 将图像转为 token 序列）、模态对齐层（如 Q-Former、线性投影将不同模态映射到同一语义空间）和 LLM 主干（统一理解和推理）。代表模型：GPT-4o、Claude 3、Gemini、Qwen-VL。

> **通俗理解**：就像一个既能看又能听还能读的全能助手。你给它一张图片，它能“看懂”内容；你给它一段录音，它能“听懂”语音。以前的 AI 只能处理文字，多模态模型让 AI 有了“眼睛”和“耳朵”。

### OCR（光学字符识别）

> **严谨定义**：OCR（Optical Character Recognition）是将图像中的文字内容转换为机器可编辑文本的技术。现代 OCR 系统基于深度学习（如 CRNN、Transformer-based 模型），包含文本检测（Text Detection）、文本识别（Text Recognition）和后处理三个阶段。企业级 OCR 还需处理版面分析、表格还原、手写体识别等复杂场景。

> **通俗理解**：就像你的眼睛扫描文档后把文字“抄”下来。但 AI 的 OCR 比人抄得更快——一秒钟能处理几十页。不过它也会犯错，比如把“Kubernetes”看成“Kubemetes”，所以需要后续校验。

### 文档解析管线（Document Parsing Pipeline）

> **严谨定义**：文档解析管线是将非结构化文档（PDF/图片/扫描件）转换为结构化数据的处理流程。典型管线包括：格式检测（文字型/扫描型）→ 文本提取（PDFBox/OCR）→ 版面分析（标题/段落/表格识别）→ 阅读顺序还原 → 清洗（去噪/去页眉页脚）→ 结构化输出（Markdown/JSON）。每个环节独立可插拔，可单独评估质量。

> **通俗理解**：就像一个“简历加工厂”。不管简历是 Word、PDF 还是拍照的，先统一“拆解”成干净的文本，再交给 AI 分析。每个环节专人负责，哪个环节出问题就修哪个，不用推倒重来。

### 3.1 多模态大模型

**GPT-4o / Claude / Gemini / Qwen-VL / GLM-4V**

能力：看图 → 理解内容 → 回答问题

**示例**：

- 输入：候选人身份证照片 → 输出：`{"name": "张三", "id": "110101...", "valid": true}`
- 输入：产品界面截图 → 输出："登录按钮在右上角，布局紧凑，建议增加留白"

### 3.2 企业应用场景（HR 方向）

1. **证件识别**：身份证、学历证 → 结构化提取
2. **截图分析**：招聘平台截图 → 提取岗位信息
3. **头像审核**：候选人头像合规性检查
4. **手写简历**：拍照 → OCR + 理解
5. **UI 审查**：产品截图 → 设计规范检查

### 3.4 批量图片处理的企业级设计

```java
// 批量图片处理服务（带错误处理和重试）
@Service
public class BatchImageProcessor {
    private final ChatClient chatClient;
    private final ExecutorService executor = Executors.newFixedThreadPool(5);

    public List<ImageAnalysisResult> processBatch(List<ImageResource> images) {
        List<CompletableFuture<ImageAnalysisResult>> futures = images.stream()
            .map(img -> CompletableFuture.supplyAsync(() -> {
                try {
                    String result = chatClient.prompt()
                        .user(u -> u
                            .text("提取图片中的关键信息，输出JSON")
                            .media(detectMediaType(img), img.getResource()))
                        .call().content();
                    return new ImageAnalysisResult(img.getId(), result, true);
                } catch (Exception e) {
                    return new ImageAnalysisResult(img.getId(), e.getMessage(), false);
                }
            }, executor))
            .toList();

        return futures.stream()
            .map(CompletableFuture::join)
            .toList();
    }

    private MediaType detectMediaType(ImageResource img) {
        // 根据文件头或扩展名判断
        String name = img.getResource().getFilename();
        if (name.endsWith(".png")) return MediaType.IMAGE_PNG;
        if (name.endsWith(".jpg") || name.endsWith(".jpeg")) return MediaType.IMAGE_JPEG;
        return MediaType.IMAGE_PNG; // 默认
    }
}
```

```
│              ↓                                          │

└──────────────────────────────────────────────────────────┘
```

### 4.1 文档解析的层级

**层级 1：文本提取**（PDF 有文字层）

- PDFBox / pdfplumber / pdf.js → 直接提取文字
- 局限：复杂排版（多栏、表格）容易乱序

**层级 2：OCR**（扫描件/图片型 PDF）

- PaddleOCR / Tesseract / 云 OCR（阿里/腾讯/百度）
- 局限：手写体、低清扫描件准确率下降

**层级 3：版面分析 + 语义理解** ⭐

- 阿里 DocMind / 腾讯 OCR / 开源 Unstructured / MinerU
- 能力：识别标题/段落/表格/图片 → 还原阅读顺序
- **这是企业级文档解析的主流方案**

**层级 4：多模态大模型直接读**

- GPT-4o / Qwen-VL 直接看图理解文档
- 灵活但 token 贵、超大文档受限

### 4.2 文档解析管线（生产级）

```
PDF 上传
  → 格式检测（文字型 or 扫描型）
  → 文字型：PDFBox 提取（快）
  → 扫描型：OCR（慢但必要）
  → 版面分析（表格还原、阅读顺序）
  → 清洗（页眉页脚、乱码）
  → 结构化文本（Markdown/JSON）
  → 交给下游（RAG 入库 / LLM 分析）

你的项目实践（记忆确认）："统一简历文本提取实践"
  正是把各种简历格式 → 统一纯文本/结构化数据
```

### 4.3 表格解析（最容易错的部分）

**难点**：

- 复杂表头（合并单元格）
- 跨页表格（表头重复）
- 无边框表格

**方案**：

1. **专用表格模型**：Table Transformer、阿里表格识别
2. **提示词技巧**：让 LLM 按"行列结构"理解
3. **多方案融合**：OCR 表格 + LLM 修正

> 解析后的表格要人工抽查 + 结构化校验

## 五、语音处理（面试场景核心）

### 5.1 语音转文字（ASR）

**服务/工具**：

- 云端：阿里 Paraformer、腾讯 ASR、讯飞、OpenAI Whisper API
- 开源：Whisper（本地部署，中文效果不错）
- 实时：流式 ASR（面试直播场景）

**企业面试场景**：

1. 面试录音 → 转写文本（离线）
2. 实时面试 → 实时转写（辅助面试官）
3. 转写文本 → LLM 分析（面试评估）

> 转写质量影响后续一切：口语化、重复词、语气词 → 需要清洗；方言/专业术语 → 准确率下降，需纠错

### 5.2 转写后处理

- **原始转写**："那个...嗯...我做过三年的 Java，就是那个...Spring Boot 项目"
- **清洗后**："我做过三年的 Java，主要是 Spring Boot 项目"

**清洗步骤**：

1. 去语气词（嗯、啊、那个）
2. 去重复（结巴修复）
3. 标点规范化
4. 分段（按语义）
5. 说话人分离（多人对话）

然后才能喂给 LLM 做面试评估

### 5.3 面试评估的完整链路

面试录音 → ASR 转写 → 清洗分段 → LLM 分析

- → 评估维度（表达能力/技术准确/逻辑/风险点）
- → 结构化报告 → 面试官参考

> ⚠️ **注意**：AI 评估只能"辅助"，最终决策必须人工（招聘合规要求 + 模型幻觉风险）

### 7.1 用 ChatGPT 分析文档图片

```
🧑 提问（ChatGPT-4o）：
[上传一张复杂表格简历的截图]
"请提取这张简历图片中的所有信息，按以下JSON格式输出：
 {name, phone, email, education[], experience[], skills[]}"

🤖 ChatGPT 输出：
- 成功识别了 90% 的信息
- 表格中的“工作经历”部分正确还原了时间线
- 但有一个技能标签被误识别（"Kubernetes" → "Kubemetes"）
- 手机号识别正确

💡 启发：
  多模态大模型直接读图片的能力已经很强，但仍有 OCR 级别的识别错误。
  最佳实践：先用专业 OCR 提取文字，再用 LLM 理解内容，两者结合效果最好。
```

### 7.2 用 Claude 处理语音转写文本

```
🧑 提问（Claude 3.7）：
"以下是一段面试录音的转写文本（未清洗），请帮我：
 1. 去除语气词和重复词
 2. 按语义分段
 3. 提取面试官和候选人的对话
 4. 总结候选人的关键技术回答

原始文本：
'面试官：那个...请你介绍一下你做过的最复杂的项目。

🤖 Claude 处理结果：
- 清洗后文本：去掉了 15 个语气词，修复了 3 处结巴
- 对话分段：正确识别了 8 轮问答

💡 启发：
  Claude 的文本清洗能力非常出色，特别是语义分段和说话人识别。
  这可以替代手写正则清洗规则，节省大量开发时间。
```

## 八、多模态应用架构要点

### 6.1 管线设计

**多模态任务 = 解析管线 + LLM 理解**

`[原始文件] → [解析服务] → [结构化文本] → [LLM 理解] → [业务结果]`

**解析服务（可独立扩展）**：

- 图片 → OCR
- PDF → 版面分析
- 语音 → ASR
- 视频 → 抽帧 + ASR

**好处**：

1. 解析结果可复用（同一简历解析一次，多次使用）
2. 解析失败可单独重试（不影响 LLM 层）
3. 各环节可独立评估质量

### 6.2 成本策略

解析环节（OCR/ASR）通常比 LLM 便宜很多

**策略**：

- 优先用便宜的解析服务
- 只有复杂理解才用多模态大模型

| 文件类型 | 方案 | 成本 |
| --- | --- | --- |
| 文本型 PDF | PDFBox 免费提取 | 免费 |
| 清晰图片 | 便宜 OCR | 几厘钱/张 |
| 复杂文档 | 文档智能服务 | 中等 |
| LLM 理解 | 只做"理解"不做"提取" | 贵 |

> **原则**：能拆就拆，LLM 只做"理解"

### 6.3 质量评估

每个解析环节都要有质量指标：

| 环节 | 指标 | 检测方式 |
| --- | --- | --- |
| OCR | 字符准确率 | 抽样人工核对 |
| ASR | 字错误率（WER） | 自动计算 |
| 版面 | 段落还原正确率 | 抽样检查 |
| 表格 | 单元格还原正确率 | 结构化校验 |

> 质量不达标 → 触发人工处理流程（质检工单）

## 九、多模态实战案例（HR 系统）

**案例 1：AI 简历全自动入库**

1. 上传 PDF 简历（含扫描件）
2. 格式检测 → 文字型 PDFBox / 扫描型 OCR
3. 版面分析 → 结构化（教育/经历/技能 分节）

5. 失败样本 → 人工处理队列
6. 成功 → 入库 + 生成文本版（供 Embedding/RAG）
7. 定期抽检 → 质量报告

**案例 2：AI 面试助手**

1. 面试录音 → Whisper 转写
2. 清洗分段 + 说话人分离
3. LLM 分析（表达/技术/风险）
4. 生成面试报告 → 面试官复核

## 十、本课小结

> **核心要点**：

1. 企业数据是多形态的：图片/PDF/语音/视频
2. 文档解析四级：文本提取 → OCR → 版面分析 → 多模态 LLM
3. **表格是最容易出错的部分**，需要专门方案
4. 语音：ASR 转写 + 清洗（语气词/重复）+ 说话人分离
5. 管线设计：解析服务（便宜、可复用） + LLM 理解（贵、灵活）
6. 每个环节都要有质量指标和人工兖底
7. **AI 评估只能辅助，最终决策必须人工**

## 十一、思考题

1. **你们项目的简历导入，扫描件 PDF 怎么处理？现在有没有 OCR？**
2. **"解析"和"理解"为什么要分成两个环节？合在一起有什么问题？**
3. **面试转写文本里有很多语气词，直接喂 LLM 会怎样？**
4. **如果 OCR 准确率只有 90%，对下游简历分析的影响是什么？怎么兜底？**
5. **多模态大模型直接读图片 vs OCR+LLM 两步走，各自的优缺点是什么？**
