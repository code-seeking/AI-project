## 一、选型的三个维度

```
选模型 = 在 质量、成本、合规 三角中找平衡

        质量（准不准、聪不聪明）
        /\
       /  \
      /    \
  成本      合规/安全
（贵不贵）  （数据出不出域）
```

**没有最好的模型，只有最适合场景的模型。**

## 二、三大部署模式对比

### 2.1 云 API（调用大厂服务）

```
优点：
  ✓ 质量最高（GPT-4o、Claude 等前沿模型）
  ✓ 零运维（不用管 GPU、模型升级）
  ✓ 按量付费（起步成本低）
  ✓ 开箱即用（SDK 成熟）

缺点：
  ✗ 数据出域（隐私合规问题！）
  ✗ 成本随量增长（没有上限）
  ✗ 依赖外部（供应商故障/涨价/停服）
  ✗ 无法定制（不能微调模型本身，部分支持）

适用：非敏感数据、对质量要求高、不想运维
```

### 2.2 私有化部署（自己跑开源模型）

```
优点：
  ✓ 数据不出域（合规安全）
  ✓ 成本封顶（硬件一次性投入）
  ✓ 完全可控（模型、服务、升级自己定）
  ✓ 可微调（用私有数据训练）

缺点：
  ✗ 需要 GPU 硬件（贵：一张 A100 约 ¥5-10 万）
  ✗ 需要运维（部署、监控、升级）
  ✗ 模型能力落后云 API 1-2 代
  ✗ 技术门槛高

适用：敏感数据（简历/医疗/金融）、长期大量调用
```

### 2.3 混合模式（推荐！）⭐

```
原则：敏感任务本地，非敏感任务云端

你项目的实践（记忆确认）：
  "Ollama + 云 API + 混合模式"
  本地 Ollama：Embedding（简历向量化，数据不出域）
  云 API：复杂分析、生成（质量优先）

混合路由示例：
  简历 Embedding → 本地 Ollama（数据不出域）
  简历分析 → 云 API（内容已脱敏）
  简单提取 → 本地小模型（省钱）
  复杂推理 → 云端强模型（质量）
```

## 四、私有化部署实战

```
┌────────────────────────────────────────────────────┐
│            私有化部署决策树                          │
├────────────────────────────────────────────────────┤
│                                                    │
│  数据是否敏感？                                   │
│    ├─ 是 → 必须私有化                            │
│    │     └─ 预算够 GPU 吗？                      │
│    │         ├─ 是 → vLLM/SGLang 生产部署       │
│    │         └─ 否 → Ollama + 量化模型          │
│    └─ 否 → 云 API 更经济                        │
│           └─ 调用量 > 100万次/月？             │
│               ├─ 是 → 考虑私有化（成本封顶）   │
│               └─ 否 → 云 API 按量付费          │
└────────────────────────────────────────────────────┘
```

### 4.1 硬件需求估算

```
估算原则：参数量 × 精度字节数 = 显存需求

7B 模型 FP16（16bit）→ 约 14GB 显存 → RTX 4090(24G) 可跑
8B 模型量化 INT4 → 约 5-6GB → 消费级显卡可跑
72B 模型 FP16 → 约 144GB → 需要 2×A100(80G) 或更多
量化（GGUF/INT4）能省 4 倍显存，质量损失约 1-3%

Embedding 模型（0.5B）→ 2GB 显存 → 随便一台机器
```

### 4.2 部署工具选型

| 工具 | 特点 | 适合 |
|------|------|------|
| **Ollama** | 一键部署，CPU/GPU 都行 | 开发/小规模（你项目在用）|
| **vLLM** | 高性能推理，吞吐高 | 生产大规模 |
| **llama.cpp** | 量化运行，内存友好 | 资源受限环境 |
| **TGI** | HuggingFace 出品 | 生产部署 |
| **SGLang** | 新秀，性能强 | 生产大规模 |

```
你项目的演进路径：
  Ollama（开发调试）→ 数据量大后换 vLLM（生产）
  两者都支持 OpenAI 兼容 API → 代码不用改！
```

### 4.3 vLLM 部署示例

```bash
# 安装（需要 Python 3.9+ 和 GPU）
pip install vllm

# 启动服务（OpenAI 兼容 API）
vllm serve Qwen/Qwen2.5-72B-Instruct \
  --port 8000 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.9

# 调用方式和 OpenAI API 一样
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen/Qwen2.5-72B-Instruct", "messages": [{"role": "user", "content": "你好"}]}'
```

### 4.4 Ollama 与 vLLM 的迁移路径

```java
// 统一接口设计：切换部署工具不改业务代码
public interface LlmProvider {
    ChatResponse chat(ChatRequest request);
    EmbeddingResponse embed(EmbeddingRequest request);
}

// Ollama 实现（开发环境）
@Component
@Profile("dev")
public class OllamaProvider implements LlmProvider {
    private final String baseUrl = "http://localhost:11434";
    // Ollama API 调用实现...
}

// vLLM 实现（生产环境）
@Component
@Profile("prod")
public class VllmProvider implements LlmProvider {
    private final String baseUrl = "http://gpu-server:8000";
    // vLLM 使用 OpenAI 兼容 API，实现几乎一样
}
```

**迁移步骤**（从 Ollama 到 vLLM）：
```
1. 部署 vLLM，加载同一模型（如 Qwen2.5-7B）
2. 修改 application-prod.yml 的模型地址
3. 跑黄金数据集回归测试，确认质量一致
4. 灰度切换 10% 流量到 vLLM
5. 观察 24 小时无异常后全量切换
6. 代码零修改（因为接口统一）
```

## 五、选型决策矩阵（实用工具）

```
对每个 AI 功能，按此表打分决策：

┌──────────────────────────────────────────────────┐
│ 功能：简历分析                                     │
│                                                  │
│ 数据敏感度：中（脱敏后可出域）                       │
│ 质量要求：高（错误分析会影响招聘决策）               │
│ 调用量：每天 1000 次（量大）                        │
│ 延迟要求：中（可接受 10s）                         │
│ 成本预算：¥3000/月                                 │
│                                                  │
│ 结论：云 API 优秀模型 + 本地 Ollama 预提取          │
│       混合模式，单次成本控制在 ¥0.02 以内            │
└──────────────────────────────────────────────────┘

评估维度：
  1. 数据敏感度（高 → 本地）
  2. 质量要求（高 → 云端强模型）
  3. 调用量（大 → 分级 + 本地）
  4. 延迟要求（低延迟 → 本地/快模型）
  5. 预算（有限 → 便宜模型 + 缓存）
  6. 合规约束（强制本地 → 私有化）
```

## 六、模型评测（选型依据）

### 6.1 评测方法

```
1. 公开基准：MMLU（知识）、HumanEval（代码）、C-Eval（中文）
   参考价值：快速了解模型能力等级

2. 领域测试集：用你的真实数据测试 ⭐ 最重要！
   构建 30-50 条典型任务 → 候选模型各跑一遍
   人工打分：准确性、格式、稳定性

3. A/B 对比：小流量线上对比
   新模型 vs 旧模型 → 看指标差异

4. 成本测试：同样的任务，实测 token 消耗
   不同模型对同一任务的 token 效率差异很大
```

### 6.2 评测清单（你的 HR 场景）

```
候选模型对比表：
  模型        简历提取准确率  匹配评分合理性  平均延迟  单次成本
  GPT-4o       98%           92%          8s      ¥0.15
  Qwen-Max     97%           90%          5s      ¥0.03
  DeepSeek     96%           88%          6s      ¥0.01
  Ollama-7B    85%           70%          2s      免费

结论：性价比 → DeepSeek；质量 → GPT-4o；敏感 → Ollama
```

## 七、模型升级与迁移

```
模型是快速演进的，架构上必须"模型无关"：

1. 统一接口：Spring AI / LangChain4j 封装（你已在用）
2. 配置化：模型名、地址、密钥全部配置化
3. 不绑定特性：不依赖某模型特有功能（如某模型的特殊 tool 格式）
4. 评估先行：升级前先跑黄金数据集

你项目的实践：Spring AI 抽象层 → 换模型只改配置
这是"模型无关"架构的最佳实践
```

## 七、用 AI 工具实际体验

### 7.1 用 ChatGPT 做模型评测对比

```
🧑 提问（ChatGPT-4o）：
"我有以下 5 个模型评测结果，请帮我生成一个综合评分矩阵，
 权重分配：质量 40%、成本 30%、延迟 20%、合规 10%。
 输出排名和推荐方案。"

 模型    质量分  成本(元/次)  延迟(s)  合规
 GPT-4o    95     0.15       8       云端
 Qwen-Max  92     0.03       5       云端
 DeepSeek  88     0.01       6       云端
 Ollama-7B 70     0          2       本地
 Ollama-72B 85    0          15      本地

🤖 ChatGPT 分析结果：
- 综合评分（归一化后加权）：
  Qwen-Max: 87.5 分（性价比之王）
  DeepSeek: 82.3 分（最便宜，质量稍弱）
  GPT-4o:   78.1 分（质量最高但成本拉低）
  Ollama-72B: 65 分（合规但延迟高）
  Ollama-7B: 58 分（快但质量差）
- 推荐：混合方案，日常用 Qwen-Max，敏感数据用 Ollama-72B

💡 启发：
  AI 工具能快速做加权评分计算，比手动算快得多。
  可以把这个评分模板固化成团队的选型工具。
```

### 7.2 用 Claude 分析硬件规划

```
🧑 提问（Claude 3.7）：
"我们公司要私有化部署 Qwen2.5-72B 模型，预计每天处礆 5000 次请求，
 每次平均输入 2000 tokens + 输出 500 tokens。
 请帮我规划 GPU 硬件方案，包括：型号、数量、预估成本、是否需要量化。"

🤖 Claude 分析：
- 72B FP16 需要 ~144GB 显存，最少 2×A100-80G
- 5000 次/天 ≈ 0.06 QPS 平均，峰值 0.3 QPS
- 推荐方案：
  方案 A：2×A100-80G（FP16，质量最佳，硬件 ~¥15 万）
  方案 B：1×A100-80G（INT4 量化，质量损失 ~2%，硬件 ~¥8 万）
  方案 C：4×RTX 4090（INT4 量化，消费级，硬件 ~¥6 万，但稳定性差）
- 建议：生产环境选方案 A，测试环境选方案 B

💡 启发：
  Claude 给出了三个方案对比，还考虑了峰值并发和稳定性。
  特别有价值的建议：测试环境用量化版本可以节省一半成本。
```

## 八、本课小结

```
核心要点：
1. 三种部署模式：云 API（质量）、私有化（合规）、混合（推荐）
2. 混合模式：敏感数据本地 + 非敏感云端
3. 硬件估算：7B FP16 ≈ 14GB 显存，量化省 4 倍
4. 工具选型：Ollama（开发）→ vLLM（生产）
5. 选型决策：数据敏感度/质量/量/延迟/预算/合规 六维评估
6. 评测：领域测试集 > 公开基准，实测 token 成本
7. 架构必须模型无关（Spring AI 抽象层）
```
