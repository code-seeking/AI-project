# 第 22 课：AI 测试与评估体系

> **核心问题**：怎么证明 AI 功能"变好了"？怎么防止改坏了？
> **预计时间**：2 天
> **前置知识**：第 17 课（Prompt 工程）、第 21 课（可观测性）

---

## 一、传统测试 vs AI 测试

```
传统软件测试：
  输入固定 → 输出固定 → 断言相等
  assert(result == expected)

AI 测试：
  输入固定 → 输出"不固定"（概率生成）！
  无法断言"相等"，只能断言"质量达标"

传统测试思维移植到 AI 会失败：
  ❌ assert(aiAnswer == "标准答案")
  ✅ assert(aiAnswer 包含关键要点 && 格式合法 && 无编造)
```

## 二、AI 评估的四个层级

```
┌──────────────────────────────────────────────────────────┐
│           AI 评估四层模型                                │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  层级 4: 价值评估  │ 采纳率↑ 招聘效率↑ 满意度↑      │
│  ─────────────────────────────────────────────────────  │
│  层级 3: 业务评估  │ 分析专业✓ 结论合理✓ 可用✓      │
│  ─────────────────────────────────────────────────────  │
│  层级 2: 内容评估  │ 关键信息✓ 忠实度✓ 无编造✓      │
│  ─────────────────────────────────────────────────────  │
│  层级 1: 格式评估  │ JSON合法✓ 字段齐全✓ 范围正确✓  │
│                                                          │
│  自动化程度：层级1 高 → 层级4 低                      │
│  业务价值：  层级1 低 → 层级4 高                      │
└──────────────────────────────────────────────────────────┘
```

```
层级 1：格式评估（最容易自动化）
  输出是否合法 JSON？
  字段是否齐全？数值范围是否正确？

层级 2：内容评估（半自动）
  是否包含关键信息？
  是否与给定资料一致（忠实度）？
  有没有编造（幻觉检测）？

层级 3：业务评估（需要业务专家）
  分析是否专业？
  结论是否合理可用？

层级 4：价值评估（最终目的）
  采纳率有没有提升？
  招聘效率有没有改善？
  用户满意度如何？
```

## 三、黄金数据集（Golden Dataset）

### 3.1 构建方法

```
什么是黄金数据集：
  一批"输入 + 期望输出标准"的测试用例
  每次改动后跑一遍，判断"变好还是变坏"

构建步骤：
  1. 收集真实场景输入（历史请求、典型问题）
  2. 人工标注期望输出（专家写标准答案）
  3. 覆盖边界情况（空输入、超长、异常格式）
  4. 持续扩充（线上失败的案例 → 修正 → 入库）

规模建议：
  起步：30-50 条（先跑起来）
  成熟：200-500 条（覆盖全面）
  每条都要"人工审核过的标准答案"
```

### 3.2 用例结构

```json
{
  "case_id": "RA-001",
  "feature": "resume_analysis",
  "input": {
    "resume_text": "张三，男，2019-2024年在XX科技任Java开发..."
  },
  "expected": {
    "score_range": [60, 100],
    "must_include": ["Java", "经验年限"],
    "must_not_include": ["编造信息"],
    "json_schema": "resume_analysis_v2"
  },
  "tags": ["中文", "正常简历"],
  "source": "线上日志-20260715"
}
```

## 四、评估执行方式

### 4.1 自动化回归（每次改动必跑）

```
触发时机：
  每次修改 Prompt / 切块 / 检索策略 / 模型
  每次发版前

流程：
  1. 加载黄金数据集（按功能筛选）
  2. 逐条执行 AI 功能
  3. 逐条评估（格式 + 内容 + 关键点）
  4. 生成回归报告（通过率、失败清单）
  5. 失败率 > 阈值（如 10%）→ 阻止发布

你项目实践：自动化测试体系（auto-test 目录）已有基础
  → 把 AI 回归接入现有测试体系
```

### 4.2 LLM-as-Judge（用 AI 评 AI）

```
原理：用强模型（GPT-4o）给被测模型的输出打分

评估维度提示词：
  "请评估以下回答：
   1. 是否忠实于给定资料（1-5）
   2. 是否回答了问题（1-5）
   3. 是否存在编造（1-5，5=无编造）
   4. 格式是否规范（1-5）
   输出：{'faithfulness':4, 'relevance':5, 'hallucination':5, 'format':4}"

注意：
  裁判模型本身的偏差（偏向自己的输出风格）
  需要校验裁判一致性（同一输出跑两次，打分是否稳定）
  开源替代：Prometheus（专门训练的裁判模型）
```

### 4.3 LLM-as-Judge Java 实现

```java
// LLM-as-Judge 评估服务
@Service
public class LlmJudgeService {
    private final ChatClient judgeClient; // 用强模型做裁判

    public JudgeResult judge(String input, String output, GoldenCase expected) {
        String judgePrompt = """
            你是一个严格的质量评估专家。请评估以下 AI 输出：

            【输入】
            %s

            【AI 输出】
            %s

            【评估标准】
            1. 忠实度(1-5)：输出是否忠实于输入信息，不编造？
            2. 相关性(1-5)：输出是否回答了问题？
            3. 完整性(1-5)：是否包含关键信息：%s？
            4. 格式规范(1-5)：输出是否符合 JSON schema？

            输出 JSON：{"faithfulness":N, "relevance":N, "completeness":N, "format":N, "reason":"简要说明"}
            """.formatted(input, output, String.join(",", expected.getMustInclude()));

        String judgeOutput = judgeClient.prompt()
            .user(judgePrompt)
            .call().content();

        return parseJudgeResult(judgeOutput);
    }

    // 裁判一致性检查：同一输出跑两次，打分差异 < 1
    public boolean isConsistent(String input, String output, GoldenCase expected) {
        JudgeResult r1 = judge(input, output, expected);
        JudgeResult r2 = judge(input, output, expected);
        return Math.abs(r1.totalScore() - r2.totalScore()) <= 1;
    }
}
```

### 4.4 人工抽检

```
自动化不能覆盖的（业务专业性）：
  面试评估是否专业？
  推荐理由是否打动 HR？

机制：
  1. 每日抽检：随机抽取 5% 的 AI 输出，人工打分
  2. 专家评审：业务专家定期评审（周会）
  3. 反馈闭环：评审结果 → 进入数据集 → 下次回归覆盖

你项目实践：AI 建议支持"一键执行" + 人工确认
  → 修正记录就是天然的评估数据！
```

## 五、评估指标设计

### 5.1 核心指标（每个 AI 功能都要有）

```
正确率：黄金用例通过率（最核心）
召回率：关键信息提取完整度
幻觉率：编造信息比例（应该趋近 0）
格式合规率：JSON 合法比例
延迟：P50/P95
成本：单次调用 token/费用

业务指标（更高层）：
  采纳率：AI 输出被人工采纳的比例
  修正率：人工修改 AI 输出的比例
  满意度：用户反馈
```

### 5.2 指标看板

```
看板布局：
  第一行：各功能"正确率 + 采纳率"（核心）
  第二行：趋势（近 30 天）
  第三行：失败用例 Top10（待分析）
  第四行：成本趋势

数据来源：黄金回归结果 + 线上日志 + 反馈表
```

## 六、A/B 测试（线上评估）

```
场景：新 Prompt / 新模型 / 新策略上线前

设计：
  对照组（A）：旧方案（50% 流量）
  实验组（B）：新方案（50% 流量）
  样本分配：按用户 ID 取模（同一用户固定一组，体验一致）

对比指标：
  正确率（抽样人工评）
  采纳率、修正率
  延迟、成本
  用户反馈

时长：至少观察 3-7 天（收集足够样本）
结论：B 明显更优 → 全量；无差异 → 保守起见留 A；更差 → 下线
```

## 七、用 AI 工具实际体验

### 7.1 用 Claude 生成黄金数据集

```
🧑 提问（Claude 3.7）：
"请帮我构建 10 条简历分析功能的黄金测试用例，每条包含：
 - 输入简历（简短但真实）
 - 期望评分范围
 - 必须包含的关键信息
 - 不应该出现的内容
 - 边界情况标记

要求覆盖：正常简历、空简历、超长简历、非中文简历、
包含特殊字符的简历、工作经验不足的、过度包装的。"

🤖 Claude 生成的用例覆盖了：
- 正常简历（3 条）：不同年限、不同技术栈
- 边界用例（4 条）：空输入/超长/纯英文/特殊字符
- 异常用例（3 条）：经验不足/过度包装/信息矛盾

💡 启发：
  AI 工具生成的用例覆盖度很好，但“期望评分范围”需要人工调整。
  建议：AI 生成 80% + 人工修正 20%，特别是边界用例的期望值。
```

### 7.2 用 ChatGPT 设计 A/B 测试方案

```
🧑 提问（ChatGPT-4o）：
"我要对简历分析功能做 A/B 测试，对比新旧两版 Prompt。
 请帮我设计完整的实验方案，包括：
 - 样本量计算
 - 分组策略
 - 评估指标
 - 实验时长
 - 统计显著性检验方法"

🤖 ChatGPT 方案：
- 样本量：每组至少 200 次调用（基于 80% 统计功效，α=0.05）
- 分组：按用户 ID 取模，A 组旧版，B 组新版
- 主要指标：采纳率（AI 结果被 HR 接受的比例）
- 次要指标：评分合理性、JSON 合规率、延迟、成本
- 时长：至少 7 天（覆盖工作日+周末）
- 检验方法：双样本 t 检验（连续指标）/ 卡方检验（比率指标）

💡 启发：
  AI 工具给出的样本量计算和统计方法非常专业。
  关键发现：200 次是最低要求，如果采纳率差异很小（如 5%），
  可能需要更多样本才能检测到显著差异。
```

## 八、持续评估闭环

```
┌─────────────────────────────────────────────┐
│                评估闭环                       │
│                                             │
│  线上日志 ──→ 失败案例收集 ──→ 人工修正        │
│     ↑                        ↓               │
│  发布 ──→ 回归测试 ←── 黄金数据集扩充          │
│     ↓                        ↑               │
│  灰度/A-B ←── 优化（Prompt/模型/策略）        │
└─────────────────────────────────────────────┘

关键：评估数据要"越用越多"
  每个线上失败案例 → 修正 → 进数据集
  数据集越大 → 回归越严 → 系统越稳
```

## 九、各环节评估方法速查

| 环节 | 评估方法 | 自动化程度 |
|------|---------|-----------|
| Prompt 改动 | 黄金数据集回归 | 高 |
| 模型升级 | 数据集 + 领域测试 | 高 |
| 切块策略 | 检索召回率评估 | 高 |
| 检索质量 | 期望文档命中率 | 高 |
| RAG 回答 | 忠实度 + 相关性（LLM-Judge）| 中 |
| 业务判断 | 专家抽检 | 低 |
| 整体价值 | 采纳率/效率指标 | 低 |

## 十一、本课小结

```
核心要点：
1. AI 输出不固定 → 不能断言"相等"，只能评估"质量"
2. 四层评估：格式 → 内容 → 业务 → 价值
3. 黄金数据集：30-500 条，人工标注，持续扩充
4. 三种执行：自动化回归 / LLM-as-Judge / 人工抽检
5. 指标：正确率、幻觉率、采纳率、修正率
6. A/B 测试：线上灰度验证方案优劣
7. 评估闭环：失败案例 → 数据集 → 回归 → 优化
```

1. **你的简历分析功能，黄金数据集最少需要多少条？怎么标注？**
