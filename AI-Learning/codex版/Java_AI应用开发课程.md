# Java AI 应用开发课程 - 自适应深讲版

生成日期：2026-08-08

本版按知识点复杂度自适应展开，不再固定每个知识点页数。

## 第 1 周：AI 应用开发认知

建立企业级 AI 应用的总视角：模型不是系统本身，AI 应用是模型、上下文、知识、工具、流程和治理组合出来的工程系统。

### LLM 与传统后端的差异
- 复杂度：核心能力
- 本质：LLM 是概率生成系统，传统后端是确定逻辑系统。企业 AI 的核心工作，是在不确定能力外面包一层确定工程边界。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### AI 应用六层架构
- 复杂度：复杂系统
- 本质：企业 AI 至少包含模型层、上下文层、知识层、工具层、编排层和治理层。缺任何一层，Demo 上线后都会暴露问题。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### Token 与上下文窗口
- 复杂度：核心能力
- 本质：模型看到的是 token 序列，不是无限记忆。上下文窗口决定模型一次能参考多少信息，也直接影响成本和稳定性。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 模型能力边界
- 复杂度：核心能力
- 本质：模型擅长语言理解、生成和归纳，但不天然具备企业实时事实、权限判断和业务执行能力。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 幻觉的工程本质
- 复杂度：复杂系统
- 本质：幻觉不是简单 bug，而是资料不足、约束不足或目标不清时，模型仍倾向生成合理文本。工程上要用 RAG、工具、拒答和评估约束。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### AI 应用价值判断
- 复杂度：基础概念
- 本质：不是所有功能都值得 AI 化。适合 AI 的任务通常语言密集、规则复杂、信息分散、人工成本高。
- 学习动作：讲本质 -> 使用边界 -> 小练习

### Java 开发者的优势
- 复杂度：基础概念
- 本质：Java 开发者擅长系统边界、事务、权限、稳定性和工程化，这正是企业 AI 落地最缺的能力。
- 学习动作：讲本质 -> 使用边界 -> 小练习

### 从聊天到工作流
- 复杂度：复杂系统
- 本质：聊天只是入口，真正的企业价值来自把回答变成流程节点、数据更新、审批建议和可追踪结论。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### 人机协作闭环
- 复杂度：核心能力
- 本质：AI 负责分析、生成和建议，人负责目标、判断、确认和反馈，系统负责记录过程并推动迭代。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 学习路线总图
- 复杂度：基础概念
- 本质：学习要按模型调用、Prompt、Embedding、RAG、Tool、Agent、治理逐层推进，不要一开始就追复杂 Agent。
- 学习动作：讲本质 -> 使用边界 -> 小练习

## 第 2 周：模型 API 与流式聊天

把模型调用封装成稳定后端能力，重点是路由、流式、超时、fallback、成本和调用审计。

### Chat Completion 调用链路
- 复杂度：复杂系统
- 本质：一次模型调用包含 system/user 消息、参数、上下文、模型选择、响应解析和错误处理，不只是一个 HTTP 请求。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### System Prompt 与 User Prompt
- 复杂度：核心能力
- 本质：System Prompt 定义角色和边界，User Prompt 承载具体任务。两者混用会让提示词不可治理。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 模型参数 temperature/top_p
- 复杂度：基础概念
- 本质：参数决定输出稳定性和发散度。事实问答偏低温度，创意生成可提高。
- 学习动作：讲本质 -> 使用边界 -> 小练习

### SSE 流式输出
- 复杂度：复杂系统
- 本质：流式输出优化用户感知等待，但带来断线、取消、异常补偿、审计和前端状态管理复杂度。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### 模型路由策略
- 复杂度：核心能力
- 本质：不同模型适合不同任务。企业要按质量、成本、延迟、隐私和可用性做路由。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 超时、重试与 fallback
- 复杂度：核心能力
- 本质：模型服务不稳定是常态。系统必须有超时、有限重试、降级模型和友好错误。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### Token 成本核算
- 复杂度：核心能力
- 本质：成本由输入 token、输出 token、模型价格、重试、上下文长度和缓存命中共同决定。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### Prompt Cache
- 复杂度：基础概念
- 本质：重复问题或稳定上下文可以缓存，但必须注意权限、时效和个性化差异。
- 学习动作：讲本质 -> 使用边界 -> 小练习

### OpenAI 兼容接口
- 复杂度：基础概念
- 本质：兼容接口不代表行为完全一致，参数、流式、错误码和工具调用都要测试。
- 学习动作：讲本质 -> 使用边界 -> 小练习

### 模型调用日志
- 复杂度：核心能力
- 本质：日志是评估、成本、审计和安全的基础，不能只为排错记录。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

## 第 3 周：Prompt 与结构化输出

把 Prompt 当成接口协议，让模型输出能稳定进入 Java 系统。

### Prompt 是接口协议
- 复杂度：复杂系统
- 本质：Prompt 的作用是定义模型执行任务的协议，不是写一段求模型听话的作文。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### 角色与任务拆分
- 复杂度：核心能力
- 本质：角色定义模型身份，任务定义要完成的工作，拆开后才可复用、测试和治理。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 上下文选择
- 复杂度：核心能力
- 本质：上下文围绕任务目标选择，不是越多越好。多余上下文会增加成本并引入干扰。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### Few-shot 示例
- 复杂度：核心能力
- 本质：少量高质量示例能约束输出风格和判断尺度，但示例必须覆盖边界情况。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 结构化输出
- 复杂度：复杂系统
- 本质：结构化输出让 AI 结果进入业务系统，必须配合 JSON Schema、Java record、校验和异常处理。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### JSON 修复策略
- 复杂度：核心能力
- 本质：模型偶尔会输出非法 JSON，系统需要提取、修复、重试和降级。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 输出字段设计
- 复杂度：核心能力
- 本质：字段越贴近业务决策，AI 越有价值。字段要区分结论、证据、风险、缺失信息和建议动作。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### Prompt Injection
- 复杂度：复杂系统
- 本质：用户可能通过输入诱导模型忽略规则。防护要结合系统提示词、工具权限和输出校验。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### Prompt 版本管理
- 复杂度：核心能力
- 本质：Prompt 是线上逻辑，要版本化、灰度、回滚和效果对比。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### Prompt 评估集
- 复杂度：核心能力
- 本质：没有评估集就无法判断提示词是否变好。评估集要覆盖常见、边界和失败样本。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

## 第 5 周：Embedding 与向量库

理解语义检索底层逻辑：向量模型、文本构造、索引、元数据和评估。

### Embedding 本质
- 复杂度：复杂系统
- 本质：Embedding 把文本映射到高维向量空间，让语义相近的文本在距离上更接近。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### 向量维度
- 复杂度：基础概念
- 本质：维度由 embedding 模型决定，不同模型向量空间不可混用。
- 学习动作：讲本质 -> 使用边界 -> 小练习

### 相似度度量
- 复杂度：核心能力
- 本质：常见度量有 cosine、dot product、L2，必须和模型训练方式及索引匹配。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### 语义文本构造
- 复杂度：核心能力
- 本质：向量化前的文本组织决定召回质量，要把业务字段合成模型能理解的语义画像。
- 学习动作：讲本质 -> 拆组件 -> 工程化 -> 验收

### Chunk 策略
- 复杂度：复杂系统
- 本质：chunk 影响召回粒度。太大干扰多，太小语义不足，要按标题、段落和语义边界切。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理

### Metadata 设计
- 复杂度：复杂系统
- 本质：元数据用于权限、过滤、溯源和版本治理，是生产级向量库关键。
- 学习动作：讲本质 -> 拆组件 -> 画全流程 -> 工程示例 -> 生产治理
